- Kotlin + Jetpack Compose + Material 3.
- Hilt для DI.
- Room для локальной БД.
- Пакет: `com.example.fitapp`.
- `minSdk = 26`, `compileSdk = 34`, `targetSdk = 34`.

## APK и локальная раздача

Последний APK 0.4.18 был собран в отдельной временной копии, потому что Windows блокировала `app/build` в исходной папке:

```text
C:\Users\alex1on1ce\AppData\Local\Temp\GymAPP-build-0418\app\build\outputs\apk\debug\app-debug.apk
```

На момент передачи Python-сервер запущен на порту 8000 и раздаёт эту папку. Ссылка для телефона в той же Wi‑Fi сети была:

```text
http://10.50.6.11:8000/app-debug.apk
```

IP может измениться при переподключении к сети. Нужно определить текущий IPv4 компьютера и запустить:

```powershell
python -m http.server 8000 --bind 0.0.0.0
```

из каталога с APK. Не использовать `127.0.0.1` для телефона: он доступен только самому компьютеру.

## Где сейчас застряли

По последней пользовательской задаче код исправлен, unit-тесты и APK 0.4.18 собраны. Нужна только проверка пользователем на физическом телефоне.

Ранее APK 0.4.16 падал сразу после запуска на телефоне. Точный `logcat` получить не удалось: ADB не видел подключённых устройств. Наиболее вероятной причиной были перекодированные WebP-иллюстрации. В 0.4.17 эти изменения полностью откатили и вернули исходные PNG; версия 0.4.18 также использует PNG.

Если приложение снова упадёт:

1. Не гадать по скриншоту.
2. Подключить телефон через USB или Wireless debugging.
3. Проверить `adb devices -l`.
4. Снять `adb logcat` с фильтром `AndroidRuntime` и пакетом `com.example.fitapp`.
5. Исправлять только после получения stack trace.

## Грабли: чего нельзя повторять

1. **Не переводить все exercise PNG в WebP без теста на реальном телефоне.** Такая оптимизация уменьшила APK примерно со 123 МБ до 22 МБ, но версия с WebP падала на устройстве. Исходные PNG сейчас намеренно восстановлены.
2. **Не оставлять фиктивные метрики.** Нельзя показывать проценты, калории или прирост, если они не рассчитаны по данным пользователя. Особенно нельзя снова добавлять `0.68f`, `progressFor(id)` или похожие декоративные значения.
3. **Не собирать из `app/build`, если Windows держит блокировку.** В исходной папке нередко возникает `AccessDeniedException` на `app/build/intermediates/.../mergeDebugResources`. Лучше создать отдельную чистую копию проекта в `%TEMP%` и собрать в ней.
4. **Не удалять чужие неотслеживаемые файлы.** В исходной папке могут быть пользовательские `docs/` и `.serena/`; они не входят в релизные коммиты.
5. **Не использовать `127.0.0.1` как ссылку для телефона.** Нужен LAN-IP и `--bind 0.0.0.0`.
6. **При явном запросе на APK обязательно делать релизный цикл:** поднять версию, обновить `CHANGELOG.md`, собрать APK, проверить и закоммитить только относящиеся изменения.
